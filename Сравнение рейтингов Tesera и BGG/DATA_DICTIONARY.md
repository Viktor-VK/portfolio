**Формат CSV:** разделитель столбцов `;`, десятичный разделитель `,`, кодировка UTF-8 с BOM (открывается в Excel
и Power BI с русской локалью без настроек). Целые числа без дробной части. Пустая ячейка - значения нет.

**Ноль как «нет данных».** В API Tesera отсутствующее значение часто приходит как `0`, а не как пустое: у игр без
оценок BGG `bgg_avg_rating = 0`, у игр без заполненного времени партии `playtime_max = 0` и т.п. В узких таблицах

ячейками; в остальных числовых полях `0` нужно читать как «не заполнено», если по смыслу значение не может быть
нулевым.

**Значения `list_sort`** (это параметр сортировки API Tesera):

| Значение | Выборка |
|---|---|
| `-ratingn10` | топ Tesera: по убыванию байесовского рейтинга n10 |
| `-ratinggeekbgg` | топ BGG: по убыванию geek rating |

**Единицы (`unit`):** `pts_10` - баллы по шкале 1-10; `votes` - число оценок; `users` - число пользователей;

**Ключ строки.** Одна игра повторяется во многих строках. Уникально строку определяет набор

## 5. Как устроены рейтинги

Коротко: **все рейтинги берутся с сайта готовыми.** Оценок отдельных пользователей в данных нет, поэтому
средние заново посчитать нельзя. Но связи между рейтингами можно проверить, и для Tesera они восстанавливаются
формулами почти без погрешности.

Обозначения: `v` - число оценок игры, `R` - её средняя оценка.

### 5.1. Средняя оценка Tesera (`tesera avg_rating`)

Среднее арифметическое оценок пользователей по шкале 1-10. Берётся с сайта; вывести из собранных данных нельзя,
так как индивидуальные оценки не собирались.

### 5.2. Байесовские рейтинги Tesera (`bayes_n10_rating`, `bayes_n20_rating`)

Средняя оценка, «притянутая» к общему среднему: к реальным оценкам игры добавляются `m` виртуальных оценок,
равных априорному среднему `C`. Чем меньше у игры реальных оценок, тем сильнее её рейтинг сдвигается к `C` -
так игра с тремя оценками «10» не обгоняет признанные хиты.

```
bayes_m = (v * R + m * C) / (v + m)
```

- `m = 10` для `bayes_n10_rating` и `m = 20` для `bayes_n20_rating` (следует из названия поля);
- `C` Tesera не публикует. Восстановлено из данных: если выразить `C` из формулы для каждой игры,
  получается почти константа - медиана 6,40, у 80% игр от 6,30 до 6,50.

**Проверка:** с `C = 6,4` формула воспроизводит `bayes_n10_rating` с точностью до округления (±0,01) у 97,7%
игр, `bayes_n20_rating` - у 97,8%. Средняя ошибка 0,003. Остальные расхождения, вероятно, из-за того, что
рейтинги и число оценок в API обновляются не одновременно.

Пример, «Звёздные войны: Восстание»: `v = 847`, `R = 8,82` ->
`(847 * 8,82 + 10 * 6,4) / (847 + 10) = 8,79`; на сайте - 8,79.

**Вывод:** байесовские рейтинги Tesera можно вывести из собранных данных, если принять `C = 6,4`.

### 5.3. Суб-рейтинги и итоговая оценка Tesera

Суб-рейтинги - средние оценки пользователей по четырём критериям. Итоговая средняя оценка совпадает со средним
арифметическим четырёх суб-рейтингов:

```
avg_rating ≈ (gameplay + depth + originality + implementation) / 4
```

**Проверка:** совпадение с точностью ±0,01 у 99,5% игр, средняя ошибка 0,003. Судя по всему, пользователь
Tesera ставит оценки по четырём критериям, а итог считается как их среднее.

**Следствие для анализа:** корреляция отдельного суб-рейтинга с итоговой оценкой завышена по построению - итог
состоит из этого же суб-рейтинга. Поэтому связь критериев изучается через корреляции суб-рейтингов между собой.

### 5.4. Рейтинги BGG (`bgg avg_rating`, `bgg num_votes`, `geek_rating`)

Tesera хранит копию трёх полей BGG; дата последней синхронизации неизвестна.

- **`avg_rating`** - среднее арифметическое оценок пользователей BGG (шкала 1-10). Берётся готовым.
- **`geek_rating`** - байесовский рейтинг BGG, по нему строится топ BGG. Официально BGG формулу не раскрывает;
  известно, что к оценкам добавляются виртуальные оценки около 5,5, а также применяется фильтрация накруток.
  **Из наших данных формула не восстанавливается:** если принять `C = 5,5` и выразить число виртуальных оценок `m`,
  оно не постоянно (медиана около 2 600, растёт вместе с числом реальных оценок; корреляция 0,81). Значит, модель
  «фиксированное `m` виртуальных оценок» для BGG не подходит, и geek rating используется как готовое значение.

## 6. Производные метрики и формулы

Считаются в `make_wide.py`, `analysis.py` и ноутбуке.

### 6.1. Разница оценок

```
diff = tesera_avg_rating - bgg_avg_rating
```

Больше 0 - на Tesera игру оценивают выше, меньше 0 - выше на BGG. Сравниваются средние оценки, а не байесовские:
у площадок разные механизмы притяжения, и их разница смешалась бы с разницей вкусов.

### 6.2. Фильтр для сравнения

Игра участвует в сравнении, если `tesera_num_votes >= 20` и `bgg_num_votes >= 100`. Порог отсекает игры со
случайными средними; игры без привязки к BGG (`bgg_id = 0`) отсекаются автоматически. После фильтра - 661 игра
из 756.

### 6.3. Показатели эффекта отбора

Считаются отдельно по каждой выборке (топ Tesera, топ BGG) и по объединению:

```
средняя разница            = mean(diff)
медиана разницы            = median(diff)
доля игр, где Tesera выше  = count(diff > 0) / count(*)
```

### 6.4. Период выпуска

`tesera_year_published` группируется в интервалы: до 2000, 2000-2009, 2010-2014, 2015-2019, 2020-2022, 2023+.
По каждому считается `mean(diff)` только по базовым играм (`is_addition = False`).

### 6.5. Разница по жанрам

Для базовых игр жанры из `tesera_genre` разворачиваются: игра с двумя жанрами попадает в оба. По каждому жанру
считается `mean(diff)`; показываются жанры с 10+ играми.

### 6.6. Спрос на барахолке

```
buy_per_sell = tesera_buying_now / max(tesera_selling_now, 1)
```

Сколько пользователей хотят купить игру на одного продающего. Знаменатель ограничен снизу единицей, чтобы не
делить на ноль. Счётчики накопленные, поэтому метрика подходит для сравнения игр между собой, а не для оценки
текущего дефицита. Для таблицы по Hobby World берутся игры с `tesera_owners >= 300`.

### 6.7. Частота издателя

Число игр в объединённой выборке, у которых издатель есть в `tesera_publisher`. Игра с несколькими издателями
засчитывается каждому.

## 7. Статистические методы

| Метод | Где применяется | Что проверяет |
|---|---|---|
| t-тест для одной выборки (`scipy.stats.ttest_1samp`) | средняя разница оценок | отличается ли `mean(diff)` от нуля |
| U-тест Манна-Уитни (`scipy.stats.mannwhitneyu`) | дополнения против базовых игр | различаются ли распределения `diff` у двух групп; не требует нормальности |
| Корреляция Спирмена (`scipy.stats.spearmanr`) | оценки площадок, год выпуска и разница, суб-рейтинги | монотонная связь двух величин; устойчива к выбросам. ρ от -1 до 1 |

**p-value** - вероятность получить такой же или больший эффект, если на самом деле эффекта нет. Меньше 0,05 -
эффект считается статистически значимым. При сотнях игр даже маленькие эффекты бывают значимыми, поэтому рядом
всегда указывается и размер эффекта.

| Tesera | tesera.ru - крупнейший русскоязычный сайт о настольных играх |

| Топ BGG | список игр по убыванию geek rating |
| Базовая игра | самостоятельная игра (`is_addition = False`) |
| Дополнение | расширение к базовой игре, без неё не играется; в данных - флаг `is_addition` или связь «исходная игра» (`addition` заполнено) |
| Байесовский рейтинг | средняя оценка, сдвинутая к общему среднему тем сильнее, чем меньше оценок у игры (см. 5.2) |
| Эффект отбора | искажение вывода из-за того, как отобрана выборка: в топ площадки попадают игры с завышенными на ней оценками, поэтому в «своём» топе площадка выглядит щедрее |
| Узкая таблица | формат «одна строка - одно значение»: удобно хранить разнородные и многозначные поля в одной схеме |
| Широкая таблица | формат «одна строка - одна игра, метрики в колонках»: удобно для анализа и сводных |
| Барахолка | раздел Tesera с объявлениями о продаже и покупке игр между пользователями |
