# Синтетические данные для проектов портфолио

Рабочие расчёты в проектах кластеризации и скоринга шли по реальным данным компаний, которые публиковать
нельзя; проект цепи поставок сразу построен на симуляции. Чтобы ноутбуки выполнялись и строили графики, здесь лежит генератор одной базы
**DuckDB** с обезличенными синтетическими данными: структура таблиц повторяет исходные источники (DWH аптечной
сети, учётная система сети электроники), а сами строки сгенерированы.

Сама база (около 20 МБ) в git не хранится: она собирается локально, ноутбуки в репозитории сохранены вместе
с выводом и графиками, а на сайт уходят готовые JSON для графиков (`export_site_data.py`).

**Цифры в базе не описывают ни одну реальную компанию.** Выводы в ноутбуках - демонстрация методов, а не
факты о бизнесе.

## Состав

| Файл | Что это |
|---|---|
| `synthetic_projects.duckdb` | сама база (собирается локально, в git не хранится) |
| `generate.py` | точка входа: собирает все схемы, `--scale dev` (маленькие таблицы для разработки) или `--scale full` |
| `pharmacy_products.py` | справочник товаров аптечной сети |
| `pharmacy_sales.py` | точки продаж, чеки, остатки, действующая ассортиментная матрица |
| `supply_chain.py` | симуляция цепи поставок сети электроники: поставщик, склады, магазины |
| `raw/` | исходный файл открытых данных (в git не хранится, см. ниже) |

```bash
python generate.py --scale full   # собрать базу
# выполнить ноутбуки: кластеризация -> скоринг -> цепь поставок (они пишут результаты в схему results)
python export_site_data.py        # выгрузить JSON для страниц сайта
```

Генерация детерминирована (фиксированный seed): повторный запуск даёт ту же базу.

## Схема `pharmacy` - аптечная сеть

Используется проектами «Кластеризация точек продаж» и «Скоринг и выбор ассортиментной матрицы».

| Таблица | Содержимое |
|---|---|
| `products` | товары: МНН, торговое наименование, производитель, АТХ, лекформа и её группа (таблетки, капсулы, саше, порошок...), дозировка, фасовка и число доз в упаковке, категория и подкатегория, розничная цена, признаки СТМ и минимального ассортимента |
| `stores` | точки: бренд сети, бизнес-единица, тип (аптека / оптика), площадь зала, выкладка ОФТ/ЗФТ, локация, даты открытия и закрытия, текущая категория A-E |
| `cheques` | строки чеков: дата и время, количество, суммы до скидки, со скидкой и по закупке, тип продажи (розница, интернет-заказ, маркетплейс, опт), остаточный срок годности |
| `stock` | снимок остатков по точкам на конец периода |
| `matrix_fact` | действующая ассортиментная матрица по текущей категории точки |
| `store_archetypes` | скрытый архетип точки - только для проверки качества кластеризации |

**Откуда товары.** Лекарства - из открытого Государственного реестра предельных отпускных цен на ЖНВЛП
([grls.rosminzdrav.ru](https://grls.rosminzdrav.ru/PriceLims.aspx), архив на 28.09.2026, лист «Действующие»).
Из 54 тыс. строк реестра оставлены розничные формы (без инфузий, лиофилизатов, больничных упаковок,
контрастных средств), разобраны лекформа, дозировка и фасовка, по АТХ назначены категории. Розничная цена
получена из предельной цены производителя с условными надбавками. Нелекарственный ассортимент (БАД,
гигиена и косметика, мать и дитя, медизделия, оптика) и его бренды выдуманы.

**Как устроены продажи.** Каждой точке назначен скрытый архетип: центральная аптека, классическая, у дома,
дискаунтер, премиум, в ТЦ, сельская, при поликлинике, оптика. Архетип задаёт площадь, трафик, размер чека,
уровень цен, склонность покупателей к дешёвому или дорогому товару внутри подкатегории и категорийный микс.
Товары имеют популярность с длинным хвостом, небольшие точки держат не весь ассортимент. В чеки добавлены
строки, которые должны отсекать бизнес-фильтры: опт, маркетплейсы, уценка по сроку годности, нетоварные
позиции.

## Схема `supply` - цепь поставок сети электроники

Используется проектом «Сквозной анализ цепи поставок».

| Таблица | Содержимое |
|---|---|
| `products` | номенклатура: смартфоны Apple (названия моделей реальные), модель, ассортиментный статус |
| `branches` | склады и магазины, привязка магазина к складу |
| `prices` | цена продажи и себестоимость (условные) |
| `supplier_orders` | еженедельные заказы поставщику по складам: заказано, подтверждено, дата поступления |
| `journal` | журнал движений: поступления от поставщика и со склада, отгрузки в магазины, продажи |
| `stock_now` | текущий остаток складов и магазинов и товар в пути |
| `truth_daily` | истинный остаток на начало дня и спрос покупателей - только для проверки |
| `truth_events` | проблемы, заложенные в симуляцию, - только для проверки разбора |

Движения получены дневной симуляцией: закупщик раз в неделю заказывает товар на каждый склад по средним
отгрузкам склада за 3 недели, поставщик подтверждает заказ целиком или частично, товар приходит через 2 дня;
магазины каждый день заказывают у своего склада (точка заказа - 2 дня продаж, максимум - 5 дней), доставка
1 день. Заложены перебои у поставщика и квота на старте iPhone 17, недозаказы и перезаказы, неравномерный
закуп дефицитного товара, пропуски пополнения и перезатарка отдельных магазинов.

## Схема `results`

Сюда ноутбуки пишут свои результаты: сегменты точек и ценовые уровни товаров (кластеризация), итоговую
матрицу (скоринг).

## Исходный файл реестра

`raw/zhnvlp_2026-09-28.zip` (11 МБ) в git не хранится. Он нужен только для пересборки справочника товаров:
скачайте архив реестра на любую дату со страницы
[архива реестров предельных цен](https://grls.rosminzdrav.ru/LimPriceArchive.aspx) и положите в `raw/`
(имя файла задаётся в `pharmacy_products.py`).
