# Скоринг товара и выбор итоговой ассортиментной матрицы

**Страница с графиками на сайте:** [viktor-vk.github.io/projects/assortment-matrix](https://viktor-vk.github.io/projects/assortment-matrix/)

**Отрасль:** розничная сеть, кластеризованная на точки продаж (см.
[`../Кластеризация точек продаж`](../Кластеризация%20точек%20продаж) - там строятся сами кластеры точек,
здесь - следующий шаг: для готового кластера строится и выбирается конкретная товарная матрица).

## Задача

Для каждого товара определить, должен ли он входить в ассортиментную матрицу конкретного кластера точек
(входить в "обязательный" ассортимент этого сегмента) - не по вкусу категорийного менеджера, а по
измеримому вкладу товара в оборот и прибыль этого сегмента, и с проверкой, что предложенная матрица не хуже
уже действующей по деньгам.

## Что делает расчёт

1. **Score товара внутри юнита.** Юнит - группа взаимозаменяемых товаров (одна и та же потребность
   покупателя). Внутри юнита каждому товару присваивается Score на основе продаж, с корректировками
   (бонус/штраф) за ценовой сегмент товара - то есть не просто "сколько продано", а с поправкой на то, что
   товар решает свою задачу на своём ценовом уровне.
2. **ABC-классификация юнитов внутри кластера.** Юниты ранжируются по доле в общем Score кластера,
   дальше делятся на классы A/B/C по накопительной доле (например, первые юниты, которые в сумме дают 50%
   Score кластера - класс A, следующие до 90% - класс B, остальное - C). Это стандартный ABC-анализ, но
   применённый не к товару напрямую, а к юниту (то есть к потребности, а не к конкретному SKU).
3. **Генерация нескольких кандидатов на итоговую матрицу** - не один вариант, а сразу два разных метода,
   каждый - с несколькими вариантами параметров:
   - **экспоненциальный порог** - вероятностная граница "входит ли товар в матрицу" по экспоненциальному
     распределению скора, с разными значениями λ (более и менее строгие варианты отбора);
   - **ABC-пороги** - вручную заданный набор комбинаций (сколько нужно набрать по скору отдельно для
     класса A, B и C юнита, плюс минимальный скор товара) - несколько таких комбинаций проверяются сразу.
4. **Сравнение всех кандидатов с фактической (текущей) матрицей** по деньгам: суммарная стоимость остатка,
   выручка, прибыль, число позиций - и разница каждого кандидата с фактом. Визуализация - scatter-график
   разниц по выручке/прибыли/остаткам, чтобы видеть кандидатов, которые режут излишний остаток без потери
   выручки, а не просто "самый жёсткий отбор".
5. **Выбор одного конкретного варианта** из всех проверенных как итогового - по результатам сравнения.

Дополнительно в расчёт заведены "защищённые" позиции - товар, который должен входить в матрицу независимо
от скора (собственная торговая марка, регуляторно обязательный минимальный ассортимент) - этот механизм
подготовлен как переключаемая опция, независимо от того, какой из методов отбора выше используется.

## Где эффект для бизнеса

- **Не один умозрительный вариант матрицы, а измеримое сравнение нескольких** - решение принимается по
  фактической разнице в деньгах с текущим состоянием, а не по интуиции.
- **Явно виден выбираемый trade-off** - например, вариант, который освобождает много оборотных средств почти
  без потери выручки, а не вариант "сократить всё максимально жёстко" или "не менять ничего".
- **Механизм переиспользуем** - смена набора ABC-порогов или λ - это смена одного параметра, а не новый
  расчёт с нуля, то есть подход можно регулярно пересчитывать на свежих данных.

## Ноутбук и данные

[`01_score_abc_и_выбор_матрицы.ipynb`](01_score_abc_и_выбор_матрицы.ipynb) выполняется на синтетических данных
из общей базы [`../synthetic_data`](../synthetic_data) и берёт сегменты точек из результата ноутбука
[кластеризации](../Кластеризация%20точек%20продаж) - его нужно выполнить первым. Продажи и действующая матрица
сети сгенерированы, справочник лекарств - из открытого реестра ЖНВЛП; цифры не отражают реальный бизнес.

Что в ноутбуке:

- Score, ABC-классы юнитов (юнит - действующее вещество + форма + объём пачки) и варианты матрицы по шкале
  строгости (кривая по 10 значениям, нулевые точки - точно);
- деньги считаются **по каждой точке**: выручка и прибыль по продажам с переключением спроса на аналоги,
  **остатки - по нормативу запаса** (страховой запас + половина поставки, не меньше выкладки) для каждой пары
  «точка × товар матрицы»;
- выбор варианта правилом: минимум денег в остатках при прибыли как у действующей матрицы (прибыль по текущим
  продажам - частичная оценка, остатки сравниваются полностью, полный эффект показал бы пилот);
- для каждого способа разбить сеть строится кривая «остатки -> прибыль» и считаются две точки пересечения с
  нулевыми осями: остатки при той же прибыли и прибыль при тех же остатках;
- **проверка на отложенных неделях**: 8 недель чеков делятся пополам, сегменты и матрицы строятся по первым
  четырём, а деньги считаются по следующим четырём; так же проверяются другие способы разбить сеть - одна
  матрица на всю сеть, текущие категории точек A-E, скрытые архетипы из генератора и случайные группы.
